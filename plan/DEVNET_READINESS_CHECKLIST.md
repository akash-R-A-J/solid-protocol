# Devnet Readiness Checklist

Last updated: 2026-05-04.

Single source of truth for what blocks the SolID system (solid-protocol +
solid-console + solid-wallet) from a public devnet launch. Built from the
2026-05-04 deep audit. Tracks both the protocol repo and the two product
repos at sibling paths (`../solid-console`, `../solid-wallet`).

Scope filter: out of scope for devnet (handled separately):
- Multi-party trusted-setup ceremony (SOLID-SEC-012, mainnet blocker).
- Governance multisig on slash / fraud-proof / issuer-tree-operator
  (SOLID-SEC-013, SOLID-SEC-043, mainnet blocker).
- The documented-security backlog in `sec/SECURITY_REGISTRY.md`. The
  owner is fixing those independently before devnet deploy.

Decisions taken 2026-05-04:
- Holder UX: ship the real browser extension (`solid-wallet` Path A).
  No "credentials in console" fallback.
- Issuer UX: finish the issuer-side of `solid-console`. No separate CLI
  for v0.

## Critical-path summary

Estimate: 23-30 days end-to-end. Critical path is item 2 (verifier
wrapper); every product item depends on it. Items 4.1 (CDN) and 1.x
(deploy) are parallelizable from day one.

## 1. Protocol -- on-chain layer

This layer is already devnet-ready. These items execute the deploy,
they do not block it.

| #   | Item                                                                                                                                                | Why                                                                                                                                                                                                                                                | Status |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 1.1 | Run `scripts/initialize.ts` against `--provider.cluster devnet`.                                                                                    | Deploys all three programs at the canonical IDs. This is the moment the system goes from "localnet green" to "live on devnet."                                                                                                                     | open   |
| 1.2 | Run main VK chunked upload + finalize + freeze, and subgroup VK chunked upload + finalize + freeze.                                                  | The verifier programs are useless without VKs loaded. Freeze locks them under the 48-hour ADR-0015 timelock so rotation requires a real ceremony, not a `--force`.                                                                                  | open   |

Without this, integrators have no machine-readable manifest of what is deployed.                                                            | open   |

If those accounts do not exist on devnet, every `verify_batch_proof_v2` call reverts -- even with a valid proof.                                  | open   |
| 1.5 | Sample-data seed: bootstrap one demo issuer (with on-chain BJJ subgroup proof) and one demo schema (e.g. `kyc_basic_v1`).                           | Without a sample issuer + schema, integrators have nothing to point `verifyRequirement` at. ## 2. TS SDK -- `@solid-protocol/verifier` high-level wrapper

The single biggest devnet blocker.

| #   | Item                                                                                                                                                                                                  | Why                                                                                                                                                                                                                                                                                                                                                                                                                  | Status |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 2.1 | Implement `verifyRequirement({ wallet, schema, predicates, action })` per `plan/VERIFIER_SDK_SHAPE.md`.                                                                                              | Today integrators must call `verifyOnChainV2()` directly: build proof buffer, derive ~12 PDAs, reconstruct merkle paths, manage nullifiers, pin VK artifact bytes. That is the protocol talking, not a product. The wrapper is what turns "evaluating SolID" into "integrated in 15 minutes." Without it the Superteam-listing pitch ("private eligibility verification for Solana apps") has no surface to integrate against. | open   |
| 2.2 | Implement `defineRequirement(...)` and the typed error contract (`MISSING_CREDENTIAL`, `EXPIRED_CREDENTIAL`, `REVOKED_ISSUER`, `UNSUPPORTED_SCHEMA`, ...).                                            | Integrators need a predictable error set to branch on -- "verification failed, here is why" instead of "tx reverted with InstructionError(0, Custom(6042))". The console and demo app both need to switch on these.                                                                                                                                                                                                  | open   |
| 2.3 | Wire artifact pin chain (`SOLID_*_SHA256` env > sidecar `*.sha256` > config defaults) into the wrapper's WASM/zkey loader.                                                                            | Already exists at `ts-sdk/packages/sdk/src/artifact_integrity.ts` (SEC-058). The wrapper has to consume it, otherwise integrators can be silently fed wrong artifacts and produce proofs against the wrong VK.                                                                                                                                                                                                       | open   |
| 2.4 | Publish `@solid-protocol/verifier@0.2.0` and `@solid-protocol/sdk@0.3.0` to npm.                                                                                                                       | Right now nothing is on npm. Console + demo + wallet cannot `npm install` what they need; they would have to monorepo-link. Devnet integrators cannot install at all.                                                                                                                                                                                                                                                | open   |

| 5.3 | Add `snarkjs`, the circuit `.wasm`/`.zkey` artifacts (loaded from CDN per 4.1, pin-checked per 2.3), and the WASM bridge from `@solid-protocol/core`.                                            | `groth16.fullProve()` needs all three. | 5.6 | Add `chrome.action.openPopup()` in the service worker so dApps can trigger proof requests.                                                                                                         | When a dApp calls `window.solid.requestProof()`, the popup never opens automatically (`solid-wallet/src/background/service-worker.ts`). The user has to click the toolbar icon manually.                                                                                                                                                                                       | open   |
| 5.7 | Generate manifest icons (16/48/128 px) referenced by `manifest.json` but missing from `public/`.                                                                                                  | Manifest references `icons/icon-{16,48,128}.png` (manifest.json:10-12, 26-30); the files are absent.
