## 1. Verdict

The code is better than the docs claim and the docs are more confident
than the code warrants. The post-remediation work landed: the verifier's
owner-checks, schema-ordering, atomic replay PDA, chunked VK, slashing
transfer, approve-via-trust-anchor, and monotonic root updates are all
real in `programs/` and match `docs/POST_REMEDIATION_AUDIT.md`. But
three **critical, mainnet-blocking** defects survived remediation --
(1) the batch circuit is under-constrained on
`queryCredentialIndices`/`queryFieldIndices` and is a complete soundness
break; (2) `register_schema` has its Poseidon hash integrity check
commented out; and (3) `issue_credential` never binds the `merkle_tree`
pubkey or the `schema_hash` to a registered schema. Combined, these
three let any approved issuer fabricate a universe of rogue schemas
and mint proofs that satisfy arbitrary predicates over fictitious
credentials. Everything else -- the VK freeze-gate, the in-circuit
issuer binding, the nullifier-per-PDA scale ceiling, the single-party
trusted setup, the 1/11 integration tests, the single-key slashing
authority, the WASM bridge that CI builds from the wrong directory --
is serious-but-fixable engineering debt. **This is a credible v0.3
testnet. It is not mainnet-safe, and the canonical backlog in
`docs/IMPROVEMENTS_ROADMAP.md` lies about what's closed.**

## 2. Findings

All findings in this audit are registered in `sec/SECURITY_REGISTRY.md`.
Short-form below; full remediation, regression gates, and status live in
the registry.

### CRITICAL

| ID            | Title                                                                        | Evidence |
|---------------|------------------------------------------------------------------------------|----------|
| SOLID-SEC-001 | Batch circuit: `queryCredentialIndices` / `queryFieldIndices` unconstrained  | `circuits/batch_credential_query.circom:56-59,216-217`; `circuits/lib/predicate_evaluator.circom:85-112` |
| SOLID-SEC-002 | `register_schema` Poseidon integrity check commented out                     | `programs/schema-registry/src/lib.rs:114-130` |
| SOLID-SEC-003 | `issue_credential` missing schema + tree pubkey binding                      | `programs/issuer-registry/src/lib.rs:619-716,909-937` |

#### SOLID-SEC-001 detail

The batch circuit declares `queryCredentialIndices[MAX_PREDICATES]` and
`queryFieldIndices[MAX_PREDICATES]` as public inputs with no range
constraints. `BatchFieldSelector` computes
`credIs[i].out * selectors[i].value` and returns 0 for any out-of-range
index. A prover sets `credIndex = 1000`, `queryValue = 0`,
`operator = EQ` and satisfies `result = 1` for any predicate without
holding any credential. Full soundness break on batch proofs.
`compound_query.circom` is affected at `FieldSelector` identically.
Remediation requires `LessThan(8)` range checks on every index and a
new trusted setup.

#### SOLID-SEC-002 detail

```rust
// programs/schema-registry/src/lib.rs:114-130
// We use light-poseidon for on-chain verification
// (Simplified for this task, in production we use the solid-core trait)
// let computed_hash = solve_poseidon(hash_inputs);
// require!(computed_hash == schema_hash, ErrorCode::InvalidSchemaHash);
```

Anyone can register a schema with an arbitrary `schema_hash` that does
not correspond to the declared metadata. SEC-06 in the remediation audit
is not actually closed.

#### SOLID-SEC-003 detail

`issue_credential` derives `PDA(b"tree-authority", schema_hash)` but does
not: (a) require `schema_hash` correspond to a registered schema;
(b) bind `merkle_tree.key()` to `SchemaTreeBinding.tree_pubkey`;
(c) prevent an approved issuer from appending to any SPL-AC tree whose
authority is `PDA(b"tree-authority", any-32-bytes)`. An approved issuer
can spawn a rogue schema/tree universe that the on-chain verifier
accepts as canonical.

## 4. Invariants NOT verified (specialist re-exam recommended)

1. **Circomlib Poseidon vs `light-poseidon` byte equality.**
   `test_hash_bytes_matches_hash_fields` only tests internal-Rust
   consistency. No Rust-vs-Circom snapshot exists. CLAUDE.md advertises
   `tests/vectors/commitment_and_nullifier.json` as gating
   Rust <-> Circom parity; it does not (see SOLID-SEC-010).
2. **BJJ EdDSA signed-message interop.** Rust signs deterministically
   via `Blake2b(sk||msg)`. Circomlib reference signer uses SHA-512 over
   `sk`-clamp || msg. Different `(R8, S)` outputs for identical inputs
   are algebraically acceptable but break any downstream system that
   hashes `(R8, S)` expecting reproducibility.
3. **Alt_bn128 subgroup enforcement.** `groth16-solana` is a dependency
   for pairing; independent confirmation that
   `alt_bn128_pairing` rejects non-subgroup G1/G2 elements was not
   performed in this audit.
4. **`negate_g1_point` edge cases at Y=0 and Y=P-1.** Unit test
   comment says "accepted by groth16-solana canonicalization"; not
   independently verified.
5. **Circom `IsZero` template resolution across the include graph.**
   See SOLID-SEC-022. Specialist should compile and inspect the final
   R1CS.
6. **SPL-AC append discriminator stability across versions.**
   `SPL_AC_APPEND_DISCRIMINATOR = [0x95, 0x78, ...]`
   (`programs/issuer-registry/src/lib.rs:39`) is hard-coded and brittle
   across future SPL-AC instruction-name changes.
7. **Compute-unit ceiling on `verify_batch_proof` under load.**
   Estimated 280-320K CU with ~80-120K headroom against the 400K
   default (1.4M if bumped). Specialist should profile on devnet under
   realistic load.
8. **Indexer race window** between `issue_credential` (issuer-registry
   appends leaf) and `update_tree_root` (schema-registry mirrors).
   Affects availability; attacker can exploit mempool observation to
   cause benign proof failures.
9. **`ark-ed-on-bn254::Fr` subgroup order** equals the BJJ subgroup
   order. Code assumes yes; arkworks source not independently checked.
10. **Groth16-solana canonicalization** behavior for edge pairing
    inputs.

## 5. Integration / cohesion audit

The code is cohesive; the WASM packaging is fractured; the docs are
drifting.

### Workspace cohesion

- Root `Cargo.toml` members (`crates/solid-core`, `crates/solid-light`,
  three programs, `wasm`) all present.
- `tools/solid-prover` is a deliberate separate workspace due to
  `ark-circom` version conflict; correctly scoped in CI.
- `ts-sdk/packages/*` all present and consumed by the
  `@solid-protocol/sdk` aggregator.
- Cosmetic issue: mixed `workspace:*` vs pinned `"0.1.0"`/`"0.2.0"`
  specifiers across TS packages.

### Real fractures

- **WASM bridge** (SOLID-SEC-009): three disagreeing sources of truth.
  CI builds from `crates/solid-core`, SDK imports from
  `../../../wasm/pkg`, Cargo declares the `wasm` feature in
  `solid-core` but no exports exist there. The `wasm/` crate holds
  the actual bridge code. This is the single biggest integration hole
  in the repo.
- **Dead TS test infra**: every `ts-sdk/packages/*/package.json:9`
  declares `"test": "jest"` but ships no tests, no Jest config.
  `npm test --workspaces --if-present` in CI is an effective no-op.
- **Misleading crate name**: `crates/solid-light` parses SPL-AC
  bindings (Light Protocol is not integrated). Rename or document
  prominently.
- **Contradicting audit artifacts**: `security_audit.md` and
  `solid_protocol_system_audit_2026_04_21.md` at the root contradict
  `docs/POST_REMEDIATION_AUDIT.md` and are not referenced from
  `CLAUDE.md`. They predate the remediation by one day.

## 10. Phased plan -- no workarounds, no regressions

Each phase has entry criteria, exit criteria, regression gates, and an
explicit no-workaround rule for the trickiest items.

### Phase 1 -- Unbrick (target: 4-6 weeks)

Goal: eliminate the three CRITICAL findings and the E2E-breaking bugs
before anything else.

| Item          | Root-cause fix (no shortcut)                                                                                                 | Regression gate |
|---------------|------------------------------------------------------------------------------------------------------------------------------|-----------------|
| SOLID-SEC-001 | Add `LessThan(8)` range checks on `queryCredentialIndices[i]` and `queryFieldIndices[i]` in both circuits. New trusted setup.| Property-based witness-generation test + on-chain rejection test. |
| SOLID-SEC-002 | Re-enable `solve_poseidon(hash_inputs) == schema_hash` using `light-poseidon` on-chain. Approx 170K CU, acceptable.           | Unit test + integration test `04_schema_and_bindings`. |
| SOLID-SEC-003 | Add `schema_account` + `schema_tree_binding` required accounts to `issue_credential`. Seed-constrain + require matches.       | Integration tests `06_issue_credential_rejects_unregistered_schema` + `07_issue_credential_rejects_wrong_tree`. |
| SOLID-SEC-005 | Bind `public_inputs[30]` to `Clock::get()?` with 5-minute skew.                                                               | Integration test `10_verify_expired_credential_rejected`. |
| SOLID-SEC-011 | Fix zkey filename agreement; import / replace `keccak256HashPair`; add issuer bootstrap sequence.                             | CI job `e2e_localnet` runs full flow to on-chain verify success. |
| SOLID-SEC-009 | Pick one WASM bridge source of truth. Delete the other. Update CI + SDK path.                                                 | CI job `wasm_bridge_smoke` round-trips every primitive. |
| SOLID-SEC-027 | Flip every closed checkbox in `docs/IMPROVEMENTS_ROADMAP.md`. Archive stale docs. Purge emoji/box-drawing.                    | `scripts/check_docs.py` fails on ASCII violations + mismatched closed items. |

**No-workaround rule for Phase 1.** Every fix ships a root-cause diff
plus a regression test. No "log and continue" error paths, no
temporary `#[cfg(feature = "unchecked")]` escape hatches, no doc-only
"this is fixed" notes without code. SOLID-SEC-001 and SOLID-SEC-003 in
particular must both ship with Merkle-membership / range-check tests;
if either slips, the phase does not close.

### Phase 2 -- Close the soundness loop (target: 8-10 weeks after Phase 1)

Goal: remove the remaining HIGH-severity gaps and the remaining
regression holes.

1. **SOLID-SEC-004 -- in-circuit issuer binding.** Prefer compressed
   issuer Merkle tree with in-circuit membership over CPI (cleaner,
   does not grow `verify_batch_proof` CU). Bundle circuit changes
   with SOLID-SEC-001 and SOLID-SEC-008 into a single circuit rev +
   one trusted setup event.
2. **SOLID-SEC-006 -- VK versioning and rotation.** Add `vk_frozen`
   and `vk_generation`. Store `(vk_id, VkStorage)` as separate PDAs.
   Include `vk_generation` as a public input. Require pause for
   post-generation-0 writes.
3. **SOLID-SEC-007 -- BJJ subgroup checks.** Reject cofactor torsion
   on registration and during `pubkey_to_affine`. Arkworks
   `mul_by_cofactor().is_zero() == false`.
4. **SOLID-SEC-010 -- test-vector expansion.** Every primitive with
   a TS caller gets a vector. Add `snarkjs wtns check` vectors for
   circuit-internal signals.
5. **SOLID-SEC-008 -- nullifier epoch binding.** Include `globalRoot`
   or epoch counter in nullifier preimage. Circuit change -- bundle
   with SOLID-SEC-001 and SOLID-SEC-004.
6. **Remaining 9 integration tests.** Every row in
   `tests/integration/README.md` becomes a real test on bankrun.
7. **Schema-registry events.** `SchemaRegistered`,
   `TreeBindingCreated`, `TreeRootUpdated`, `SchemaBindingFrozen`,
   `AuthorityRotated`. Every mutable state transition becomes
   indexer-visible.
8. **Revocation v1 end-to-end.** Holder SDK stale-nonce detection and
   re-prove. Issuer SDK `bumpRevocationNonce(credentialId)`.
   On-chain `RevocationEvent` emission.

**Regression gate for Phase 2.** bankrun + anchor test + circuit
witness fuzz all green. Add `snarkjs groth16 fullprove` round-trip in
CI (currently only R1CS is compiled).

### Phase 3 -- Production infrastructure (target: 12-16 weeks after Phase 2)

Goal: cross from "testnet-shaped protocol" to "real infra your Head
of Security signs off on."

1. **SOLID-SEC-012 -- multi-party trusted setup.** Minimum 10
   contributors, attestation chain published, zkey hosted on
   IPFS + Arweave with content addressing. Pin final hash in
   `sec/SECURITY_REGISTRY.md`, `deployments/mainnet.json`, and the
   go-live audit snapshot.
2. **SOLID-SEC-013 / SOLID-SEC-016 -- governance + multisig.**
   Verifier authority and registry DAO-authority through Squads
   multisig with 48h timelock on VK rotation and 24h challenge
   window on slashing.
3. **External audit** (OtterSec / Halborn / Trail of Bits). Publish
   the report. Any CRITICAL-equivalent finding resets the mainnet
   clock.
4. **SOLID-SEC-021 -- scale escape: nullifier storage + tree depth.**
   Compressed nullifier Merkle tree or epoch-bucketed Bloom filters
   with false-positive retry. Ship depth-24 circuit rev in the next
   setup (16x capacity). No workaround acceptable.
5. **Finalized-commitment SDK path.** Add `'finalized'` helpers for
   every verify call.

## 11. Discipline rules for Phase 1 execution

Read this before starting Phase 1.

- **No workarounds.** A workaround in this codebase means shipping a
  new CRITICAL. SOLID-SEC-001 is fixed by a new trusted setup, not by
  a documentation note. SOLID-SEC-002 is fixed by re-enabling the
  Poseidon check, not by "we'll validate off-chain."
  SOLID-SEC-003 is fixed by adding the accounts to `issue_credential`,
  not by a tighter issuer-approval policy. Every shortcut here is
  soundness-visible.
- **No regressions.** Every Phase-1 fix adds a regression test;
  phases only close when the test stays green on `main` for a full
  sprint. CI must gate every invariant in `CLAUDE.md` -- today only
  two of five are gated.
- **No doc lies.** Either the doc matches the code or the doc moves
  to `docs/archive/` with a banner. `IMPROVEMENTS_ROADMAP.md` must be
  auto-generated from a single truth source (the registry here);
  two canonical docs cannot disagree.
- **One source of truth per artifact.** WASM bridge, program IDs,
  VK, circuit build outputs -- each has exactly one canonical location
  referenced by everything else.
- **External audit is not a rubber stamp.** If the external audit
  surfaces anything equivalent to SOLID-SEC-001/002/003, the mainnet
  date slips. Do not schedule mainnet against audit completion;
  schedule it against audit-close plus one sprint.
