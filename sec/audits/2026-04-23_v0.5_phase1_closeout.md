## 1. Verdict

Phase 1 ships. Every item in the 14-item Phase 1 scope from
`plan/IMPLEMENTATION_PLAN.md` is now registry-status `Fixed` with a
landed commit, a regression-gate description, and (for every
host-reachable defect) a green host-side test.  No workarounds,
suppression, or doc-only "fixes" shipped.

The protocol is not mainnet-ready -- eight HIGH / ten MEDIUM / five
LOW / four INFO items remain, covering circuit issuer-binding
(SEC-004), VK freeze-gate (SEC-006), BJJ subgroup checks (SEC-007),
epoch-bound nullifier (SEC-008), cross-language vector coverage
(SEC-010), multi-party trusted setup (SEC-012), and the
governance-maturity cluster (SEC-013..019).  Phase 2 closes the next
tier; Phase 3 adds external audit + multi-party ceremony + mainnet.

What is legitimately production-grade after Phase 1:
  - no CRITICAL registry items remain open;
  - issue_credential is bound to a registered schema + tree (no
    more rogue-universe attack);
  - the batch circuit has sound range checks and can prove
    partial-batch (1/2/3-credential) sets cleanly;
  - the WASM bridge has one source of truth, a runtime smoke test,
    and a pinned CI build path;
  - E2E scripts run from a clean checkout (issuer bootstrap +
    schema binding + prove + verify);
  - plaintext E2E secrets never land inside the repo working tree.

## 5. Residual risks after Phase 1

Phase 2 scope (see `plan/IMPLEMENTATION_PLAN.md` Section 4.2 --
updated in the close-out commit) now takes over these, in priority
order:

1. **SOLID-SEC-004** (HIGH): no in-circuit issuer pubkey binding.
   Bundled with a circuit revision; requires either CPI into
   `issuer_registry::check_issuer_status` or a compressed issuer
   tree with Merkle-membership proof inside the circuit.
2. **SOLID-SEC-008** (HIGH): nullifier does not include an epoch /
   global root; long-lived query replay risk.
3. **SOLID-SEC-006** (HIGH): VK overwrite at chunk 0 has no
   freeze-gate.
4. **SOLID-SEC-007** (HIGH): BJJ public keys not subgroup-checked.
5. **SOLID-SEC-010** (HIGH): cross-language vectors cover only 2 of
   10 primitives.
6. **SOLID-SEC-012** (HIGH): single-party trusted setup.  Phase 3
   deliverable (multi-party ceremony); the Phase 1 TESTNET zkey is
   explicitly labelled as such in `circuits/scripts/setup.js`.
7. Governance cluster: SOLID-SEC-013..019 + SOLID-SEC-034.

The remaining LOW / INFO items are cosmetic or docstring-level and
will close opportunistically alongside Phase 2 work.

## 6. Trusted-setup status

The Phase 1 circuit changes (SEC-001 + SEC-029) invalidate the
pre-remediation zkey.  The single-party TESTNET ceremony must be
re-run from a machine that has circom 2.1.9, snarkjs 0.7.5, and
circomlib installed:

```
cd circuits
npm install
npm run compile                 # batch_credential_query.r1cs
node scripts/setup.js           # -> batch_credential_query_final.zkey
                                #    + verification_key.json
                                # Prints sha256 of the zkey for audit.
```

`scripts/initialize.ts` then uploads the fresh VK into
`verifier_config.vk_storage` on whatever cluster is being targeted.
Neither the zkey nor the VK is committed; both are per-environment
build artifacts, which is intentional (the VK lives on-chain once;
the zkey is a prover input).

Multi-party ceremony (SOLID-SEC-012) is tracked in the Phase 3
scope.
