## Executive Verdict

The system is **substantially hardened** versus prior cycles, but **not yet
e2e-ready** without workarounds. Three CRITICAL findings, eight HIGHs, and nine
MEDIUMs were surfaced that the prior audit cycle did not catch. **One closed
finding (SEC-045) should be reopened**: the closure is symptomatic, not
structural.

Two of the highest-severity findings were independently confirmed by two
sub-audits looking at different sides of the same boundary, which raises
confidence that they are real:

- **CRIT-1** (expiration not bound to issuer signature) was found by both the
  TS-SDK sub-audit (signature-side) and the circuits sub-audit (witness-side).
- The "host check substituting for circuit constraint" anti-pattern was flagged
  by the Solana, circuits, and meta sub-audits, indicating it is a recurring
  structural issue, not a single-site bug.

Sub-audit reports are summarized below; full sub-audit transcripts are not

## CRITICAL Findings

### CRIT-1 -- Expiration timestamp is not bound to the issuer signature

Severity: CRITICAL
Confirmed by: TS-SDK sub-audit (B), Circuits sub-audit (B)
Status: NEW

**Where**

- Issuer signs `commitment = Poseidon(dataHash, schemaHash, holderAx, holderAy, salt)`
  -- `crates/solid-core/src/commitment.rs:42`.
- Circuit reads `signal input expirationTimestamps[NUM_CREDS]` as a private
  holder-controlled input -- `circuits/batch_credential_query.circom:102`.
- Witness builder pulls `expirationTimestamp` from the holder-side `Credential`
  struct, which is the holder's own copy -- `crates/solid-core/src/multi_cred.rs:242`.
- Circuit's only constraint on it is `ExpirationChecker` (`circuits/lib/nullifier_expiry.circom:33`),
  which compares against `currentTimestamp` but does not bind to any
  issuer-attested value.

**Bug**

The credential expiration is purely a holder-self-reported field. A holder
edits their stored credential JSON to `expiration = 2099-01-01` (or any value),
witness generation accepts the edited value, `ExpirationChecker.valid === 1`
trivially, and the on-chain proof verifies. Issuers cannot enforce time-bound
credentials at all under v0.6.1.

**Robust Fix (no workaround)**

Include `expirationTimestamp` in the signed commitment preimage:

```
commitment = Poseidon(dataHash, schemaHash, holderAx, holderAy, salt, expirationTimestamp)
```

The signature already covers the commitment, so no new signing step is needed.
Update in lockstep:

- `compute_attestation_commitment` in `crates/solid-core/src/commitment.rs`.
- `commitHasher` in `circuits/lib/credential_atom.circom`.
- TS-SDK issuer signing path (`ts-sdk/packages/issuer/src/index.ts:208-216`).

**Regression Note**

Wire-breaking change. Existing on-chain credentials cannot be re-validated
under the new commitment shape; they must be re-issued under a schema-version
bump or marked expiration-unenforceable. Adds 1 Poseidon input, re-runs the
trusted setup. PTAU_POWER=17 has headroom. Co-land with CRIT-1b (next).

### CRIT-1b -- `ExpirationChecker` uses `LessEqThan(252)` on unconstrained inputs

Severity: HIGH (paired with CRIT-1)
Status: NEW

**Where:** `circuits/lib/nullifier_expiry.circom:33`.

**Bug**

`circomlib::LessEqThan(n)` internally requires both inputs `< 2^(n+1)` via
`Num2Bits(n+1)`. With `n=252` and an unconstrained 254-bit field input, a
prover supplying `expirationTimestamp = p - small` causes the comparator's
internal subtraction to wrap around `p`, and `Num2Bits(253)` either
over-asserts or accepts a non-canonical bit decomposition. The comparator's
output is not deterministic on adversarial inputs.

`expirationTimestamps[i]` is private and only zero-constrained on padding
slots; on active slots it is unconstrained.

**Robust Fix**

Range-check both inputs to 64 bits (matches the u64 contract the on-chain
code already assumes), then `LessEqThan(64)`:

```circom
component currentTsBits = Num2Bits(64);
currentTsBits.in <== currentTimestamp;
component expTsBits = Num2Bits(64);
expTsBits.in <== expirationTimestamp;
component lte = LessEqThan(64);
lte.in[0] <== currentTimestamp;
lte.in[1] <== expirationTimestamp;
```

+~128 constraints per active credential. Re-runs setup. Co-land with CRIT-1.

### CRIT-2 -- `compute_concurrent_merkle_root_keccak` is unsound under SPL AC concurrent semantics

Severity: CRITICAL
Status: NEW. **SEC-045 should be reopened.**

**Where:** `crates/solid-light/src/cpi_helpers.rs:586-632`. Used after the
`replace_leaf` CPI to compute the post-CPI root that gets written into
`IssuerTreeBinding.current_root`.

**Bug**

The closure of SEC-045 recomputes the post-CPI Merkle root by re-running the
caller-supplied authentication path against the new leaf. The soundness
argument assumes that "if SPL AC accepted the proof, the path is the live
path."

This is wrong under SPL Account Compression's concurrent semantics. SPL AC's
`ConcurrentMerkleTree::set_leaf` validates `(old_root, prev_leaf, proof_path)`
against any root in its `change_log` ring buffer (default 64 entries), not
only the active root. When the supplied proof matches a stale root, SPL AC
walks the change_log forward to fast-forward the proof's siblings to the
live state, then commits an updated leaf. The post-CPI active root is
`change_log[new_active_index].root`, which depends on the in-buffer deltas,
not on the user-supplied path alone.

Consequence: when the supplied path is stale, the recomputed root differs
from what SPL AC actually committed. `write_issuer_tree_binding_root` then
writes a divergent value into `IssuerTreeBinding.current_root`. Two operators
calling `revoke_issuer_atomic` back-to-back with paths computed against the
same pre-CPI root produce a binding root the SPL AC tree never had.

Outcomes:

- **(a) DoS:** legitimate proofs fail the issuer-tree gate (binding is "phantom").
- **(b) Replay:** if the divergent value happens to equal a prior legitimate
  root, proofs computed against that prior state become re-replayable until
  another binding update overwrites it.

**Robust Fix**

Stop recomputing. After `invoke_signed(replace_leaf, …)`:

1. Re-borrow `merkle_tree.try_borrow_data()`.
2. Parse the SPL AC `ConcurrentMerkleTree<MAX_DEPTH, MAX_BUFFER_SIZE>` header.
3. Read `change_log[active_index].root`.
4. Write that into `IssuerTreeBinding.current_root`.

That is, by definition, the post-CPI active root.

**Regression Note**

Risk: SPL AC layout drift across versions. Mitigate with `const_assert!` on
the offsets of `active_index` and `change_log[].root`, plus a host-side
parser test that rebuilds the layout from a known SPL AC fixture and asserts
the offsets.

### CRIT-3 -- Off-chain proving artifacts (.wasm, .zkey) fetched from CDN with no SHA-256 gate

Severity: CRITICAL
Status: NEW. Sibling to SEC-041.

**Where**

- `ts-sdk/packages/sdk/src/config.ts:32` defines
  `SOLID_CONFIG.ARTIFACT_BASE_URL = "https://cdn.solid-protocol.com/artifacts/v1"`.
- `ts-sdk/packages/sdk/src/index.ts:97-100` falls back to
  `${ARTIFACT_BASE_URL}/batch_credential_query.{wasm,zkey}` if the caller does
  not supply `circuitPaths`.

**Bug**

SEC-041 protected the on-chain VK with `SOLID_VK_SHA256`. The off-chain
prover side has no analog. A compromised CDN, DNS hijack, or supply-chain
misroute serves a backdoored zkey. Because Groth16 works under any toxic
waste known to the substituter, the malicious zkey becomes an oracle to
mint valid proofs without holding any credential. SEC-041's on-chain VK
hash gate does not catch this; the on-chain verifier accepts proofs from
any prover whose zkey was generated honestly *or* dishonestly with knowledge
of the toxic waste.

**Robust Fix**

- Pin `SOLID_CIRCUIT_WASM_SHA256` and `SOLID_CIRCUIT_ZKEY_SHA256` next to
  `SOLID_VK_SHA256` in `config.ts`.
- `prove()` MUST hash downloaded artifacts and refuse to call
  `snarkjs.fullProve` on mismatch.
- Same gate on `verifyProofLocally` in `holder/src/index.ts:707` (which
  currently `JSON.parse`'s arbitrary VK files).
- CI gate: rebuild + assert published hashes match.

**Regression Note**

None. Opt-out via `SOLID_CIRCUIT_*_SHA256=skip` for dev (off by default in
production builds).

## HIGH Findings

### H1 -- `update_issuer_tree_root` is a root-injection primitive

`programs/issuer-registry/src/lib.rs:1087-1125` accepts `new_root: [u8;32]`
from a single-key authority with no on-chain cross-check against SPL AC.
Combined with SEC-043 (single-key compromise), this is a complete
proof-forging primitive: attacker computes any 32-byte value `R`, calls
`update_issuer_tree_root(R)`, and `verify_batch_proof` accepts proofs whose
`issuerTreeRoot = R`.

**Robust Fix (option A, recommended):** Deprecate the ix entirely. Make
`append_issuer_leaf` atomic by parsing the SPL AC active root post-CPI (same
SPL-AC-header pattern used in CRIT-2's fix). Add a permissionless
`reconcile_issuer_tree_root(merkle_tree)` that takes only the tree account,
parses the active root, writes it. No caller-supplied roots ever.

**Regression Note:** Off-chain reconciliation loses an escape hatch. The
permissionless reconcile ix is the structural replacement.

### H2 -- Atomic ixs don't pre-check `old_root == binding.current_root`

`programs/issuer-registry/src/lib.rs:1407-1411` (`revoke_issuer_atomic`)
and `:1615-1620` (`request_withdrawal_atomic`) forward the caller's
`old_root` into `replace_leaf` without first asserting it matches
`IssuerTreeBinding.current_root`. Even with CRIT-2 fixed, this still admits
stale-root replay attacks under front-running, because SPL AC's changelog
will accept any root from the last 64 leaf transitions.

**Robust Fix:** `require!(old_root == binding.current_root, ErrorCode::IssuerTreeRootStale)`
pre-CPI. Surface the binding root in the SDK's ix builder so callers can
retry on `IssuerTreeRootStale`.

### H3 -- Stuck stake: tree-enrolled issuers post-Cooldown cannot recover non-slashed stake

Tracing the path:

1. `request_withdrawal_atomic` flips `Approved -> Cooldown`, replaces leaf,
   sets `cooldown_ends_at = now + 14d`. Stake unchanged.
2. After cooldown, `withdraw_after_cooldown` requires `status == Cooldown`
   (`programs/issuer-registry/src/lib.rs:627-629`) and refuses if
   `is_tree_enrolled && amount == staked_amount` (`:641-643`).
3. The only way to fully drain stake for a tree-enrolled issuer would be
   `revoke_issuer_atomic` -- which flips status to `Revoked` and does not
   refund stake. After revocation, no instruction can touch the stake
   (`withdraw_stake` is `Rejected`-only at `:466-469`; `withdraw_after_cooldown`
   is `Cooldown`-only).

Net: a voluntary, well-behaved enrolled issuer permanently loses access to
their stake. SEC-044's amendment routed full withdrawals through
`revoke_issuer_atomic` but no compensating stake-recovery path was added.

**Robust Fix:** Add `withdraw_after_revoke(ctx)` accepting `Revoked` issuers
with `staked_amount > 0` and no active dispute. 24-hour delay between
`revoke_issuer_atomic` and withdrawal so DAO can file a slash. Emit
`StakeWithdrawn` event.

### H4 -- `issue_credential` accepts non-canonical (BN254 `c >= p`) commitments

`programs/issuer-registry/src/lib.rs:1742-1745` only rejects `[0u8;32]` and
`[0xFF;32]`. A malicious issuer can pick `c1 != c2` with `c1 mod p == c2 mod p`,
producing two on-chain leaves the circuit treats as one -- enabling
nullifier-confusion attacks against revocation accounting.

**Robust Fix:** Add `solid_core::field::is_canonical_bn254_le(&[u8;32])`;
`require!(is_canonical_bn254_le(&commitment), ErrorCode::CommitmentNotCanonical)`.
Same check on `bjj_pub_key_x/y` in `register_issuer` (currently only "on
curve," not "x,y < p").

### H5 -- Schema hash binds only `(name, version, num_fields)`

`programs/schema-registry/src/lib.rs:258-261` calls
`compute_schema_hash_from_parts(&name, version, field_names.len())`. The
`category` field and the field names themselves do not contribute to
`schema_hash`. Two registrations differing only in field semantics get the
same hash; a verifier accepts a proof issued under one schema and treats it
as another.

**Robust Fix:** `schema_hash = Poseidon(name_chunks ‖ version ‖ canonical(field_names) ‖ category)`.
Update both `solid_core::schema::compute_schema_hash_from_parts` and the
off-chain SDK in lockstep. Existing schemas need re-registration; provide a
migration ix.

### H6 -- `verifyOnChain` v0/ALT path returns `verified: true` on reverted tx

`ts-sdk/packages/verifier/src/index.ts:454-487` does not inspect
`confirmTransaction(...).value.err`. The legacy `sendAndConfirmTransaction`
path throws on `err`, but the v0 path (the production path per the file's
own comments) returns the signature regardless of execution result. A
reverted `verify_batch_proof` reports `verified: true` to the caller.
Compounded: `lastValidBlockHeight` is fetched in a second `getLatestBlockhash()`
call, introducing a slot race.

**Robust Fix:** After `confirmTransaction`, check `result.value.err`;
throw on non-null. Cache one blockhash. Defense-in-depth: post-fetch the
nullifier PDA and assert it exists with the expected value.

### H7 -- `compound_query.circom` still uses broken `BabyPbk()`

`circuits/compound_query.circom:115-118` uses circomlib's `BabyPbk()`
(decomposes via `Num2Bits(253)`, fails on ~26% of canonical Fp values).
Phase-3.4 fixed this in the batch circuit via `BabyPbk254()` but missed
this file. The `holderBJJPrivKey` consistency check on line 55 is also
redundant (no soundness gain over what `IdentityAnchor` already enforces).

**Robust Fix:** Delete `holderBJJPrivKey` (line 55) and the `BabyPbk()`
block. `IdentityAnchor` already binds the holder identity. If compound_query
is dead code, remove the file outright.

### H8 -- `SOLID_DEBUG_CIRCUIT_INPUT=1` writes the holder master BJJ key to `/tmp` in plaintext

`ts-sdk/packages/holder/src/index.ts:680-684` `JSON.stringify`'s `circuitInput`
(includes `masterIdentityKey`, `holderBJJPrivKey`, `revocationNonce`, `salt`,
`attestationData`, signature scalars) to `/tmp/solid-circuit-input.json` when
the env var is set. Persistent, world-readable on macOS, and a single
`actions/upload-artifact: ./tmp` mistake leaks holder identity from CI.

**Robust Fix:** Redact private fields by default; full dump only behind a
second env var (`SOLID_DEBUG_CIRCUIT_INPUT_INCLUDE_SECRETS=DANGER_I_UNDERSTAND`),
written to a `mkdtempSync` 0700 directory.

## Recurring Issue Classes (Meta-Audit Findings)

The meta sub-audit identified five bug classes that have recurred across audit
cycles. Each can be killed by one structural change rather than fixed N times:

1. **Cross-layer wire-contract drift** -- the `[count=32, indices, wire_subset]`
   contract is hand-encoded in 5 places (Rust constants, TS constants, Circom
   doc-block, ADR-0012 table, README). Examples: SEC-031, SEC-049, SEC-054
   LB1-LB3, the `VERIFIER_NONCE_INPUT_INDEX` doc-drift below, M10. Structural
   fix: code-generated `circuits/build/public_input_contract.json` consumed by
   `build.rs` (Rust), the SDK build (TS), and `check_header.js` (Circom doc-block,
   ADR, README). Drift becomes a compile-time error.

2. **Dual-target-link != dual-target-runtime** -- host green does not imply
   BPF/WASM green. Examples: SEC-007 → SEC-048 (host passes, BPF CU exceeds),
   SEC-052 (host vs WASM disagreed on coord form). Structural fix: a 3-target
   byte-equal harness (Rust host + WASM + BPF) for every wire-touching primitive.
   Today `cross_language_vectors` covers Rust↔TS only.

3. **Hand-rolled byte constants without machine validation** -- doc-comment
   names the preimage; no test recomputes. Examples: SEC-049, SEC-032 (program
   ID), M8 above. Structural fix: CI lint that scans for `// = sha256(...)` /
   `// computed from ...` patterns and demands a paired test.

4. **Caller-MUST handler discipline** -- atomic-pair split across two ixs
   with a "caller must also call X" comment. Examples: original SEC-044
   non-atomic withdrawal, SEC-045 pre-fix. Structural fix: any "caller must"
   in a handler doc-block fails review unless the missing step is computationally
   infeasible to wire up. SEC-045 closure (now CRIT-2) was the right model;
   generalize it.

5. **Reshuffle-class circuit findings** -- canonical-encoding lattice
   incompletely tested. Examples: SEC-001, SEC-029, SEC-050, SEC-051.
   Structural fix: parametric witness-tester that enumerates every K-of-N
   layout for every K, asserts only the canonical form is admitted.
