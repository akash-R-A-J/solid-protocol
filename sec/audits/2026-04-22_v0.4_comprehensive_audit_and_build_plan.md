## 1. Full Code Verification of All 27 Existing Registry Entries

### SOLID-SEC-001 (CRITICAL) -- Circuit query indices unconstrained
STATUS CONFIRMED OPEN.
`BatchFieldSelector` at `circuits/lib/predicate_evaluator.circom:85-112` uses `IsEqual()` to
match `credIndex` against each credential slot (lines 102-104). There is NO `LessThan(N)` range
constraint on `credIndex` or `fieldIndex` before they enter the mux. An out-of-range `credIndex`
produces all-zero `credIs[i].out`, making `value = 0`. A prover sets `queryValue=0, op=EQ`
(operator=1, `IsEqual(0,0) = 1`) and trivially satisfies the predicate for any credential. This
is a COMPLETE soundness break on ALL batch proofs. BLOCKS EVERYTHING.

### SOLID-SEC-002 (CRITICAL) -- `register_schema` hash check disabled
STATUS CONFIRMED OPEN.
`programs/schema-registry/src/lib.rs:129-130`: commented out lines:

The comment says "Simplified for this task". This is a one-line re-enable. Root enabler for C-3.

### SOLID-SEC-029 (MEDIUM) -- `IdentityAnchor` always has `enabled=1`; padding slots over-constrained

- Severity: MEDIUM
- Status: Open
- Evidence: `circuits/lib/identity_anchor.circom:46-53`
  ```circom
  component globalInclusion = MerkleInclusion(GLOBAL_DEPTH);
  globalInclusion.enabled <== 1;   // always 1, even for schemaHash=0 slots
  ```
- Description. `CredentialAtom` correctly guards zero-schema padding slots:
  `enabled = 1 - isZero(schemaHash)`. But `IdentityAnchor`, which is instantiated once per
  credential slot, always sets `globalInclusion.enabled = 1`. For a padding slot (schemaHash=0),
  the circuit still requires a valid Merkle inclusion proof of the identity leaf
  `Poseidon(credAx_i, credAy_i, revNonce)` where `credAx_i` is derived from
  `Poseidon(masterKey, 0)`. The global tree would need to pre-store these zero-derived leaves.
  This is not the intended behaviour and makes proofs with fewer than 4 credentials impossible
  without pre-populating nonsensical tree entries.
- Impact. The batch circuit cannot prove with 1, 2, or 3 active credentials without the global
  tree containing zero-schema identity leaves, which is architecturally wrong.
- Remediation. Pass the `enabled` signal from the batch circuit to `IdentityAnchor`:
  ```circom
  template IdentityAnchor(GLOBAL_DEPTH) {
      signal input enabled;   // NEW -- 0 for padding, 1 for active
      // ...
      globalInclusion.enabled <== enabled;
  }
  ```
  In `batch_credential_query.circom:113-122`, add:
  ```circom
  anchors[i].enabled <== 1 - isZero[i].out;
  ```
  This is a circuit change and requires a new trusted setup. Bundle with SOLID-SEC-001 in the
  Phase 1 circuit revision.
- Regression gate. Circuit test: a 3-credential batch (one padding slot) generates a witness
  without needing any zero-schema global tree entry.
- Blocks. Correct multi-credential proofs. Combine with SOLID-SEC-001 circuit fix.

### SOLID-SEC-030 (MEDIUM) -- `stake_vault` can be drained to zero, deleting the shared PDA

- Severity: MEDIUM
- Status: Open
- Evidence: `programs/issuer-registry/src/lib.rs:1192-1206` (transfer_slashed_lamports helper)
- Description. `transfer_slashed_lamports` uses raw lamport manipulation to move funds from the
  shared `stake_vault` PDA to `dao_treasury`. If the slashed amount equals the entire vault
  balance, the vault drops to 0 lamports. A 0-lamport Solana account that is not closed via a
  `close` constraint is garbage-collected by the runtime. This destroys the shared
  `PDA([b"stake-vault"])`, making all future `register_issuer` SOL transfers fail with
  "account not found".
- Impact. Medium availability risk. Triggered when the last remaining issuer's entire stake is
  slashed (e.g., malicious issuer with no other issuers remaining). Destroys the DAO's staking
  infrastructure.
- Remediation. Before the lamport transfer, assert the vault retains minimum rent:
  ```rust
  let min_bal = Rent::get()?.minimum_balance(0);
  require!(
      vault_lamports.saturating_sub(slash_amount) >= min_bal,
      ErrorCode::StakeVaultWouldGoBelow
  );
  ```
  Alternatively (if full drain is intentional), close the account explicitly and re-initialize it
  in a separate `reinitialize_stake_vault` instruction gated behind `registry_config.authority`.
- Regression gate. Unit test: slashing exactly the vault balance fails with the new error.
- Blocks. Production safety. Close in Phase 1.

## 9. Discipline: Rules for This Codebase

1. No workarounds. SEC-001 requires a new trusted setup. SEC-002 is one line, not a doc note.
   SEC-003 requires adding accounts. No shortcuts are acceptable -- they all surface as new
   CRITICAL findings.

2. No regressions. Every fix: root-cause diff + regression test in the same PR. If the test
   does not stay green, the phase does not close.

3. One source of truth. WASM bridge: `wasm/src/lib.rs`. Program IDs: `Anchor.toml` (synced by
   `check_program_ids.py`). VK: `[b"vk-storage", config, generation]` PDA. Circuit outputs:
   `target/circuits/`. No duplicates.

4. No doc lies. When code changes, the doc changes in the same PR. `sec/SECURITY_REGISTRY.md`
   is the security source of truth. `docs/IMPROVEMENTS_ROADMAP.md` reflects the code, not
   aspirations. Every finding gets a SOLID-SEC-NNN ID before going anywhere else.

5. External audit is not a milestone -- it is a gate. The mainnet date is set against audit-close
   + one sprint. Not against audit completion. If the auditors find a new CRITICAL, the date slips.
