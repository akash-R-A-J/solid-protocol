## 1. Verdict

Phase 2 ships.  Both load-bearing soundness items in scope -- SEC-004
(in-circuit issuer binding) and SEC-008 (epoch-bound nullifier) --
are registry-status `Fixed` with a landed on-chain + circuit + SDK
implementation that holds to the same discipline as Phase 1: root
causes, no workarounds, no regressions, atomic on-chain state
transitions.

The protocol is now compliant with ADR-0014 end-to-end: every proof
submits against a Merkle-proved, BJJ-bound issuer leaf in a Poseidon
tree anchored by `IssuerTreeBinding.current_root`, and the nullifier
preimage carries that same root as its 6th Poseidon input.  Revoking
any issuer -- through `revoke_issuer_atomic` -- replaces their tree
leaf in the same transaction as the status flip, so there is no
window in which on-chain status and tree root disagree.

What's production-grade after Phase 2:
  - no CRITICAL registry items remain open;
  - every CRITICAL/HIGH soundness item from the pre-Phase-1 baseline
    is closed except the external-audit + multi-party-ceremony
    tracking items (SEC-012, SEC-007, SEC-010), which are Phase 3
    scope by design;
  - the circuit + verifier + SDK trio consume a consistent 32-input
    contract (ADR-0012 revision), and the nullifier is 6-input
    (ADR-0006 revision);
  - the E2E pipeline runs from a clean checkout without manual
    plumbing: `npm run e2e` -> init -> backfill -> bootstrap ->
    issue -> prove.

Still open (Phase 3 scope): SEC-006 (VK freeze-gate), SEC-007 (BJJ
subgroup), SEC-010 (vector coverage), SEC-012 (multi-party ceremony),
the MEDIUM governance cluster (SEC-013..019, -034), LOW/INFO
housekeeping.

## 6. ADR-0014 implementation integrity

The three impl slices together satisfy the ADR-0014 design decisions:

- **Leaf composition** is `Poseidon5(authority, bjj_x, bjj_y,
  status_epoch, revocation_nonce)`.  All three fields carrying
  non-pubkey data change on status transitions, so a leaf update
  is a visible root change; the BJJ pair in the leaf is the
  load-bearing binding that prevents the "approved authority +
  attacker BJJ key" attack.
- **Atomicity** is preserved: `revoke_issuer_atomic` bumps +
  flips + CPIs `replace_leaf` in one ix.  Legacy
  `revoke_issuer` / `slash_issuer` / `submit_fraud_proof` /
  `withdraw_after_cooldown` paths REFUSE with
  `IssuerTreeUpdateRequired` for enrolled issuers.
- **Public-input contract** (ADR-0012) bumped from 31 -> 32;
  `issuerTreeRoot` at slot [10]; all consumers (circuit, verifier,
  every SDK package) updated in lockstep; named constants in the
  verifier (`ISSUER_TREE_ROOT_INPUT_INDEX` etc.) are the handler's
  single source of truth for the shifted slots.
- **Nullifier preimage** (ADR-0006) bumped from 5 -> 6 inputs;
  cross-language vector regenerated and reviewed; a one-byte change
  in `issuer_tree_root` rotates the nullifier (SEC-008 host test).
- **Trusted-setup rerun** is documented in ADR-0012 Section
  "Migration note" and executed by `circuits/scripts/setup.js`
  (unchanged interface; produces a new zkey).

## 7. E2E pipeline contract

`npm run e2e` is canonical.  Steps + accountability:

```
tsx scripts/initialize.ts          # registry + schema + VK; skips
                                    #   issuer-tree binding (no tree yet)
tsx scripts/backfill_issuer_tree.ts # SPL AC tree + binding + enroll
                                    #   existing approved issuers
tsx scripts/bootstrap_issuer.ts    # register + DAO-approve +
                                    #   append_issuer_leaf +
                                    #   update_issuer_tree_root
tsx scripts/issue.ts               # CPI issue_credential + snapshot
                                    #   issuer preimage into state
tsx scripts/prove.ts               # seed local replicas + generate
                                    #   batch proof + verify_batch_proof
                                    #   + replay-reject check
```

Every script is re-run-safe (idempotent guards around
`already-in-use` + status checks).  State file lives in
`$XDG_RUNTIME_DIR` or `$TMPDIR` per SEC-020 (never in the repo
working tree).
