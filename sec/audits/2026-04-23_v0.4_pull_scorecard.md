## What the Pull Got Right

1. SEC-002 (CRITICAL): Done properly. `compute_schema_hash_from_parts()` is a shared
   canonical function in `solid-core` that BOTH the on-chain program and the off-chain SDK
   call. This is the right architecture -- the preimage cannot drift. 4 regression tests added.

2. SEC-005 (HIGH): Done properly. Reads `config.timestamp_skew_seconds` (a configurable PDA
   field), validates the high bytes are zero before u64 conversion (preventing the
   "overly-large timestamp" DoS), and computes a saturating window. Correct.

3. SEC-030 (MEDIUM): Done with `from.data_len()` in the rent calculation, which is the right
   approach -- if the account ever gets data in the future, the floor adjusts automatically.
   Checked subtraction on the remaining balance. Correct.

## What Is Still Blocking Everything

The two remaining CRITICALs block different things:

**SEC-001 (circuit soundness):**
  Blocks: any proof that touches a predicate. Any verifier. All of Phase 2+.
  Fix: LessThan range checks on credIndex/fieldIndex in BatchFieldSelector + IdentityAnchor
       enabled signal (SEC-029). New trusted setup required. This is the biggest remaining item.

**SEC-003 (rogue tree universe):**
  Blocks: correct credential issuance. A rogue issuer can append commitments to any SPL-AC
  tree unrelated to the registered schema. Requires adding schema_account and SchemaTreeBinding
  lookups to the IssueCredential context -- see MODULE_CONTRACTS.md Section 4.2 for the
  exact account seeds needed.

**SEC-033 (identity cohesion -- E2E blocker):**
  Blocks: any real end-to-end proof. If the holder SDK is passing the master pubkey as the
  holderPubKeyX instead of the per-schema derived key, every real proof fails at the
  CredentialAtom commitment check in-circuit. Must be verified and fixed in the SDK before
  any prove.ts run can succeed.
